# 输出模板

复制即用。`{…}` 为占位符；除「其他（请说明）」外，其他行可按需增删。

## 1. 追问（一次一问）

```
**Q{n}：{具体、可判断的一句话问题}？**

A. {选项 1}
B. {选项 2} 【推荐】—— {一句话理由}
C. {选项 3}
D. 其他（请说明）
```

规则：

- 选项 3~5 个；推荐项最多一个；信息不足时可以不推荐。
- 问题里不夹带第二个问题。
- 依赖前答时加一行引导：「基于你刚才选择的 {X}，下一个问题是……」
- 不要在提问后顺手给出实现方案或代码，这会让用户以为已经开工。

## 2. 归宿标注（在对话中简短播报）

```
✅ DECIDED：{决策点} → {结论}
🐇 RABBIT HOLE：{决策点} → 本次不做（{何时再做/触发条件}）
❌ NO-GO：{决策点} → {被排除的方案}，原因：{…}
```

播报可以合并在一轮回复的结尾，一到三行即可，不要长篇复述。

## 3. 《需求确认清单》

```
## 需求确认清单

| # | 决策点 | 结论 | 状态 |
|---|--------|------|------|
| 1 | {决策点} | {结论} | DECIDED |
| 2 | {决策点} | {结论} | RABBIT HOLE (v2) |
| 3 | {决策点} | {结论} | NO-GO |

**未覆盖的风险**：{仅当用户中途叫停时填写；否则省略}

> 以上需求是否确认？确认后我将搜索相似开源项目并询问是否复用。
```

要求：

- 结论写「可执行的事实」，不写「用户倾向于……」。反例：「大概用 React」；正例：「前端 React + Vite，后端不引入，数据存 localStorage」。
- 状态只允许三种取值，与 SKILL.md 一致。
- 清单之后停下，不追加下一步动作。

## 4. 开源项目卡片

```
**{项目名}** {链接}
Star：{n 或「未获取」}｜语言：{lang}｜许可证：{license}
核心功能：{一句话}
贴合点：{逐条对照清单，如「✅ 数据本地存储；✅ CLI 形态；⚠️ 无导出」}
差异点：{缺什么、冲突在哪}
贴合度：高 / 中 / 低
```

## 5. 复用询问

```
以上 {N} 个项目中，我建议优先看 **{项目名}**——{一句话理由}。

- 复用的代价：{需要改造的决策点}；{依赖/许可证/学习成本}
- 从零的代价：{需要自己实现的核心功能}

是否复用其中一个？还是都不复用、从零开始设计？
```

## 6. 无高贴合兜底

```
**未找到贴合度足够高的开源项目。**

最接近的是 **{项目名}**，差距在于：{缺 {功能}；技术栈为 {X} 而清单要求 {Y}}。

建议继续检索的关键词：`{kw1}`、`{kw2}`（GitHub 搜索链接：{url}）

我先把实现方案给你：{进入方案设计}
```

## 7. 高风险场景话术

**用户拒绝回答**

> 好，{决策点} 先记为 v2 待办（RABBIT HOLE），风险是 {一句话}。我们继续下一个问题。

**用户要求跳过追问**

> 可以，但先对齐代价：以下 {n} 个点还没有结论（{列表}），实现时可能返工。请回复「接受这些不确定性」，我就按当前清单继续。

**需求违法/不可行**

> 这个需求我不会继续追问或实现，原因是 {…}。如果你的真实目标是想解决 {…}，我们可以换个方向聊。
